# Design system audit — 2026-08

Scope: the full package (`tokens/`, `components/`, `layout/`, `motion/`,
`scripts/`, `bin/`) as of v2.0, immediately before the v2.1 remix-layer work
this audit fed into. Findings below are the *before* state; what closed each
gap is cross-referenced against the v2.1 changes actually shipped (see
`CHANGELOG.md` and `docs/decisions.md`).

## Summary

**Components reviewed:** 9 files, ~55 exported components/hooks/utilities
across `components/` and `layout/` | **Issues found:** 1 structural
(no external-compatibility layer) | **Score: 91/100**

The deduction is concentrated almost entirely in one dimension —
**remix readiness** — which didn't exist as a category in a stock audit
rubric until this pass. Token coverage, naming consistency, and component
completeness were all already strong, which is unusual enough to call out
directly rather than pad the report with manufactured findings to fill a
template.

## Naming consistency

| Issue | Components | Recommendation |
|---|---|---|
| None found at the token/prop level | — | Every color, spacing, radius, duration, and easing value traces to exactly one authored source (`tokens.css`'s RGB triplets); `npm run check`'s internal rules already enforce no second representation of the same value. |
| `accent` vs `tone` vs `variant` naming across components | `Button`/`Card` use `accent`; `Badge` uses `tone`; `Status` uses `tone` | Low-severity, pre-existing, not touched by this pass: `accent` implies "picks a color, may also affect shape or hover behavior" (Button, Card); `tone` implies "picks a color only, no shape axis" (Badge, Status). The split is consistent once named — not a collision, but worth a one-line note in `foundations.md` if a new component gets added and the choice isn't obvious. |

## Token coverage

| Category | Defined | Hardcoded values found |
|---|---|---|
| Colors | 8 authored RGB triplets → 40+ derived tokens (text/soft/glow×2/on-\*/wash/edge/halo per element, plus semantic) | 0 — `hardcoded-color` and `raw-neutral` rules enforce this against the package's own source, at zero findings |
| Spacing | 9-step scale (`--space-xs` … `--space-5xl`), two explicit tiers (component-scale vs. page-scale) | 0 — `arbitrary-space` rule, zero findings |
| Typography | 10-step size scale + 2 letter-spacing values + 5 line-heights, 5 font roles with hard-boundary rules | 0 — `arbitrary-type`/`tiny-type`/`uppercase-heading` rules, zero findings |
| Radius | 3-step scale | 0 — `soft-radius` rule (narrowed in v2.1 to keep catching genuinely arbitrary values after containment made the named Tailwind keys safe) |
| Motion | 1 easing curve, 3 durations, 4 element-character keyframes, CSS↔JS parity enforced | 0 — `second-easing`/`unsanctioned-duration` rules, plus an internal rule asserting the JS motion constants literally match the CSS tokens |
| Glow | 5 named tiers (aura/halo/sheen/edge/wash), each with a numeric alpha cap tracked to viewport coverage | 0 — internal rules recompute the brightest stop of every gradient/shadow token and fail above cap |

This is the strongest section of the system by a wide margin: **every**
token category already has a zero-hardcoded-value baseline, verified by an
automated checker that runs against the package's own source, not just
documented as a convention. That's uncommon enough in a personal design
system that it's worth stating as a finding in its own right, not just
background.

**Missing states, not missing components:** `Button` has no documented
`loading` state (a spinner + `aria-busy` pattern), and form controls don't
visually distinguish `readOnly` from `disabled`. Both are real, minor gaps
— genuinely out of scope for this pass (locked at plan time: new component
surface area wasn't part of v2.1), logged here so they're visible for the
next one rather than lost.

**No missing component types were found** in the sense a stock audit
usually flags (no Accordion, Tooltip, Avatar, etc.) — those are real
absences but were an explicit, agreed exclusion for this pass, not an
oversight; see "Remix readiness" below for why v2.1 makes that gap far
less costly than it used to be.

## Remix readiness *(new category — didn't exist before this audit)*

The dimension that actually motivated this audit: **how much of a
component pasted from an external source (21st.dev, shadcn, or any
Tailwind-adjacent library) survives without a rewrite pass.**

| Check | Before (v2.0) | After (v2.1) |
|---|---|---|
| shadcn semantic color names (`bg-background`, `text-muted-foreground`, …) resolve to something | ❌ — undefined Tailwind color, compiles to nothing | ✅ — aliased onto Genso tokens in the preset |
| Structural defaults (`rounded-2xl`, `duration-300`, `ease-out`) land on the sanctioned scale rather than a banned one | ❌ — generated Tailwind's own soft-radius/extra-duration/second-curve values | ✅ — contained by the preset to the real scale |
| A passed `className` can override a component's base classes | ❌ — `cx()` is a plain join, no conflict resolution | ✅ — `cn()` added, backed by `tailwind-merge` |
| `Button`'s `variant`/`size` props (the shadcn API) are accepted | ❌ — TypeScript error, unknown props | ✅ — compat shim, maps onto `accent`/`shape` |
| A checker exists that fixes (not just flags) the mechanical subset of a pasted file | ❌ — no such tool | ✅ — `genso-check --translate [--write]` |
| An icon library with a different stroke language (`lucide-react`) can be used without a wrapper | ✅ (nothing blocked it, but nothing documented it either) | ✅ — explicitly documented as allowed unconstrained |
| Loosening a specific rule for a specific pasted block is possible without disabling the whole checker | ✅ (`genso-allow`, line-scoped) | ✅ — plus `genso-allow-file` for a whole file mid-remix |

Before this pass, remix readiness was the one category actively fighting
the system's own design-goal (v2.0's "an accent is not a job title, colour
is free") — a philosophy that says "adapt anything to this system" while
the tooling made every adaptation a manual rewrite. v2.1 closes that gap
without touching the philosophy, the restraint rules, or the glow budget:
it's a translation layer sitting on top of the existing architecture, not a
replacement for it. See `docs/decisions.md` for why containment (not just
name-aliasing) was the right shape, and `docs/remixing.md` for the
practical workflow.

## Priority actions

1. **Shipped this pass:** the remix layer (preset alias + containment,
   `cn()`, `Button` compat props, `genso-check --translate`,
   `genso-allow-file`, documented per-project theming). This was the
   highest-impact gap — it blocked the stated workflow ("start from
   21st.dev inspiration, remix into this system") outright.
2. **Next candidate, deliberately deferred:** a small set of new
   components genuinely missing from the system (Accordion, Tooltip,
   Avatar) — now lower-cost to add well, since v2.1 means a pasted
   reference for any of them will mostly render correctly on first paste,
   giving a faster starting point to adapt from rather than build from
   nothing.
3. **Low-priority, cosmetic:** `Button` loading state, form control
   `readOnly` treatment, and unifying the `accent`/`tone` naming split
   with an explicit rule in `foundations.md` (not a bug, but worth writing
   down before a third naming pattern gets introduced by accident).
